How the draw works (hp-draw-v1)

  1. Before the animation starts, the server picks a random 32-byte seed and shows its SHA-256 hash on stream. Once the hash is public the seed can't be swapped.
  2. The entrant list is frozen when entries close and sorted by Kick user id. Each line is id:1 for a sub or id:0 for everyone else. The SHA-256 of those lines is the entrant list hash.
  3. Random numbers come from HMAC-SHA256 keyed with the seed, over giveawayId:listHash:drawNumber:block for block 0, 1, 2 and so on. Each block gives eight 32-bit numbers. Rejection sampling keeps every pick exactly fair.
  4. One entrant at a time is picked to survive, with weight 3 for subs and 1 for everyone else, until nobody is left. The first pick wins. There are no other weights for anyone.
  5. The potato eliminates everyone else in reverse pick order, so the runner-up goes out last.
  6. If the winner doesn't claim in time, a reroll uses the same seed and list with the draw number raised by 1 and earlier winners left out.
